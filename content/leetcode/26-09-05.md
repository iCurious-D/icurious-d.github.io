## 刷怪千倍，挥刀百万倍：这谁顶得住？

3903 打完，3904 上线。题面一个字没动，示例一个数没换，力扣只在提示栏改了一行：
`1 <= nums.length <= 10^5`。

这就像二周目重进副本：小怪的属性一个没改，血量攻击跟昨天一模一样，只是刷新数量从 100 变成 100000。

昨天那把 "每来一只怪就把全图重扫一遍"的刀，今天还敢用吗？

------

怪多一千倍，你的挥刀次数多**一百万**倍。昨天那段五行的 Python 暴力：

```python
for i in range(n):
    if max(nums[:i+1]) - min(nums[i:]) <= k:
        return i
```

在`n = 10⁵` 时，账单变成这样：

- **时间**：`max` 和 `min` 每轮各扫一趟，O(n²) = **10¹⁰ 次比较**。Python 解释执行大概每秒几千万次简单操作，你自己算这是几分钟还是几十分钟。
- **内存流量**：`nums[:i+1]` 和 `nums[i:]` 每轮合计拷贝 `n+1` 个槽位，这个数还得乘 10⁵ 轮，然后全部立刻扔给 GC。你写的不是算法，是垃圾焚烧发电。

结论：二周目禁用法术——切片。谁用谁崩。

------

#### 正解：后缀数组 + 滚动前缀

昨天已经剧透，今天就是实战。

后缀最小值倒着建好表，前缀最大值边扫边更新。时间 O(n)，空间 O(n)，数据翻一千倍，复杂度一位没动。

这就是最优解的复利：昨天多花的二十分钟，今天兑现成一道签到题。

显式循环版：

```python
def firstStableIndex(nums: List[int], k: int) -> int:
    n = len(nums)
    # 后缀最小值：suf_min[i] = min(nums[i..n-1])
    suf_min = [0] * n
    suf_min[-1] = nums[-1]
    for i in range(n - 2, -1, -1):
        suf_min[i] = min(suf_min[i + 1], nums[i])
    
    # 前缀最大值：滚动变量
    pre_max = nums[0]
    for i, x in enumerate(nums):
        if x > pre_max:
            pre_max = x
        if pre_max - suf_min[i] <= k:
            return i
        
	return -1
```

accumulate版：今天在 1e5 的数据下，它依然能打。

```python
def firstStableIndex(nums: List[int], k: int) -> int:
    suf_min = list(accumulate(reversed(nums), min))[::-1]
    for i, (pm, sm) in enumerate(zip(accumulate(nums, max), suf_min)):
        if pm - sm <= k:
            return i
	return -1
```

但注意，`[::-1]` 是一次 O(n) 的拷贝，峰值内存会翻倍。在 1e5 下毫无压力，但如果哪天真搞成 1e7，就别炫技了，显式循环才是稳如老狗。
