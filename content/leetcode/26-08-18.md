## **别滑了，滑窗滑了个寂寞**

你刷过无限滚动的瀑布流吧？屏幕一屏显示 k 条，往下滑一屏，新的进来旧的出去——这就是一个宽度为 k 的滑动窗口。

这题要你找：一个宽度为 k 的窗口从左滑到右，谁只被盖住过一次？

先别着急滑！

对于 `1 < k < n` 的一般情况，**答案天然就在两端。**

为什么？因为中间的元素是"公共依赖"——随便一个中间位置，左边总有个窗口能罩到它，右边也有一个，至少被两个窗口覆盖。跟被多个微服务同时依赖的公共组件一样，想低调都难。

而首尾元素只属于一个窗口——首元素只在第一个窗口里，尾元素只在最后一个窗口里。

但事情还没完：位置在两端只是必要条件。如果首/尾元素的值在数组别处也出现过，那个位置同样会被别的窗口罩到，导致它出现在多个窗口里。所以候选还得是**全局只出现一次的“独行侠”**。

也就是说，根本不用真滑窗，直接**看两端：谁全局唯一且更大，谁就是答案。**

当然，别忘了先处理好 k 的边界情况（对，说的就是你们俩 `k=1` 和 `k=n`）：

- `k == n`：整个数组就是一个窗口，全员只被盖住一次，直接返回最大值。
- `k == 1`：每个元素自成窗口，只有全局出现一次的才算，用 Counter 筛一遍取最大。

一般情况（`1 < k < n`）：答案只在**两端且频次为 1** 的元素里。

```python
def largestInteger(nums: List[int], k: int) -> int:
    # 全屏模式：一个窗口盖住全场
    if k == len(nums):
        return max(nums)

	# 每个元素独占一屏，必须知道全局频次
    if k == 1:
        freq = Counter(nums)
        return max((x for x, c in freq.items() if c == 1), default=-1)

	# 1 < k < n：只看两端
    return max(nums[0] if nums.count(nums[0]) == 1 else -1, nums[-1] if nums.count(nums[-1]) == 1 else -1)
```

O(n) 收工。这大概就是算法界的 lazy loading——只加载两端，中间全靠不渲染。
