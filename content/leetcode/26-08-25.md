## 倍数点名册：哈希占坑，线性抓人 

给你一个数组 `nums` 和一个整数 `k`，让你找最小的、没出现在 `nums` 里的 `k` 的正倍数。

换句话说，从 `k` 开始，沿着 `k, 2k, 3k, …` 一路检查，遇到第一个不在 `nums` 里的数，返回就完了。这题简单到让人怀疑力扣今天是不是从“新手村”随机抽了一道来凑每日任务。

------

#### **一、set 一拍，谁没来？**

最直觉的思路：把 `nums` 拍进一个 `set`，然后从 `k` 开始，每次 `+k`，第一个不在 `set` 里的就是答案。

为什么用 `set`？因为列表的 `in` 是 `O(n)`，每次查都要从头翻到尾；而 `set` 的 `in` 是 `O(1)`，直接哈希定位。

```python
def missingKMultiple(nums: list[int], k: int) -> int:
    nums = set(nums)       
    ans = k
    while ans in nums:     # 按 k 的步长逐个检查
        ans += k
    return ans     
```

循环最多跑 `len(nums) + 1` 次。数据范围 `nums.length <= 100`，最坏情况也就是把前 100 个倍数全占了，第 101 个才漏出来。这点运算量，Python 解释器还没反应过来就结束了。

------

#### **二、先过滤，再查找**

方法一里，你把 `nums` 里所有元素都塞进了 `set`——包括那些根本不是 `k` 的倍数的数。它们就像被误拉进名单的路人，虽然不影响最终结果，但白白占着哈希桶。

既然只关心 `k` 的倍数，何必把整个数组都拉进来？先把不是倍数的"蹭场子"请出去，`set` 里只留真正的候选人：

```python
def missingKMultiple(nums: list[int], k: int) -> int:
    seen = set()
    for x in nums:
        if x > 0 and x % k == 0:   
            seen.add(x)			   

    cur = k
    while cur in seen:  # 每一步都踩在点上
        cur += k
    return cur
```

先过滤、再查找，`set` 里干干净净，全是 `k` 的倍数。

你可能会说：数据量这么小，过滤不过滤有区别吗？这题确实没啥区别。但换个场景——`nums` 有 10^5 个元素，只有 1% 是 `k` 的倍数——过滤后的 `set` 就更显精瘦利落。

**先缩小范围再操作，这个习惯在数据规模大时能救命。**

------

#### 彩蛋：一个迷你版的“最小可用编号分配器”

别看这题好像只是个 `while` 循环 + `set` 的简单练习，它的核心模式——在按固定步长递增的候选编号序列中找第一个缺失项——在工程里意外地常见，而且换汤不换药：

- **IP / 端口分配**：地址池里哪些被占了、第一个可用的是哪个，本质就是找最小未占用编号。如果地址池是连续整数，对应本题 `k=1` 的特例；如果地址池被划分为固定大小的块，则完全同构——简单场景 `set` 搞定，复杂场景上位图。
- **定时任务 / 调度槽位**：系统只允许在每 `k` 秒的整数倍时间槽上执行任务，已占用部分槽位，需要找最小的空闲槽位。这个场景就是本题的直接映射——候选序列是 `k, 2k, 3k, …`，已占用集合是 `nums`。
- **数据库自增 ID 空洞检测**：删了几行数据后，自增序列里出现了"断号"。运维排查数据完整性时就是从最小 ID 开始找第一个缺失项——本质相同，步长为 1，只是通常直接用 SQL 查 `NOT EXISTS` 或者自连接。

所以，你今天写的几行代码，其实就是一个迷你版的 **“最小可用编号分配器”**。核心套路就一句话：

> **哈希占坑 + 按候选序列线性探测。**

不过，如果数据量大到内存装不下，`set` 会从“永远滴神”变成“内存刺客”。到那时你可能会需要布隆过滤器、外部排序，甚至开始写分布式系统——但今天，享受这份简单就好。
