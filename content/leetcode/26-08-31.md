想象链表是一段过山车轨道，每个节点的值就是当前轨道的高度。

局部极大值 = 山顶尖叫点，局部极小值 = 谷底尖叫点。

我们要统计这些尖叫点之间的最小距离和最大距离。
如果尖叫点不够两个，那这过山车就太无聊了，直接返回 `[-1, -1]` 表示“没意思，不坐了”。

**核心操作：三节小火车**

不用一个个点回头看，直接搞一个**滑动三连窗口**——`a, b, c = head, head.next, head.next.next`（前提：链表至少仨节点，不然 `c` 直接裂开）。

就像一列三节车厢的小火车：`a, b, c` 表示前、中、后三节车厢，`b` 是当前观察对象。

判断 `b` 是不是尖叫点，就看它是不是同时比 `a` 和 `c` 高（山顶），或者同时比 `a` 和 `c` 低（谷底）。

```python
if (a.val < b.val > c.val) or (a.val > b.val < c.val):
    # b 是山顶或谷底，尖叫点！
```

然后小火车整体前移一格：`a, b, c = b, c, c.next`。  一趟扫完，每个中间节点都被 `b` 检阅了一次。

**记录距离：三个变量算两笔账**

光找到尖叫点还不够，我们要统计这些尖叫点之间的最小距离和最大距离：

- **最大距离**：第一个尖叫点和最后一个尖叫点之间的全程长度。首尾最远。
- **最小距离**：相邻尖叫点之间的最短间隔。如果两个尖叫点中间还夹着别的尖叫点，距离只会更长。

为此需要三个变量：

- `first`：第一个尖叫点的位置，用于算**最大距离**。初始为 `0`，表示还没找到。
- `pre`：上一个尖叫点的位置，用于算**相邻尖叫点的距离**。初始设为 `-inf`（宇宙级距离，防止上来就误判）。
- `min_dis`：相邻尖叫点距离的最小值。初始设为 `inf`。

每遇到一个尖叫点：

1. 如果 `first` 还是 0，说明这是第一个尖叫点，记下 `first = i`。
2. 计算与上一个尖叫点的距离 `i - pre`，并用它更新 `min_dis`。如果是第一个尖叫点，`pre = -inf`，距离为 `inf`，不会影响结果。
3. 无论哪种情况，都要更新 `pre = i`，让当前这个尖叫点成为新的“上一个”。

遍历结束后，如果尖叫点少于两个（即 `first == 0`（根本没有尖叫点） 或 `first == pre`（只有一个尖叫点），直接用 `first >= pre` 一并处理），那就返回 `[-1, -1]`。否则：

- **最大距离** = 最后一个尖叫点的位置 − 第一个尖叫点的位置 = `pre - first`
- **最小距离** = 相邻尖叫点距离的最小值 = `min_dis`

```python
def nodesBetweenCriticalPoints(head):
    if not head or not head.next or not head.next.next:
        return [-1, -1]   # 链表太短，三连窗口都开不出来，拒绝上车

    first, pre, min_dis = 0, float('-inf'), float('inf')
    a, b, c = head, head.next, head.next.next
    i = 1   # b 的位置，head 算 0

    while c:
        if (a.val < b.val > c.val) or (a.val > b.val < c.val):
            if first == 0:
                first = i    # 第一次尖叫,记下
            min_dis = min(min_dis, i - pre)  # 更新最短间隔
            pre = i   # 更新上次尖叫位置
        a, b, c = b, c, c.next  # 小火车往前滑一格
        i += 1

    if first >= pre:    # 尖叫点不足两个,这过山车太无聊
        return [-1, -1]
    return [min_dis, pre - first]
```

**复杂度**：O(n) 时间，每个节点只被小火车经过一次。O(1) 空间，除了几个变量，没额外开数组，内存友好。  

**友情提示**：链表长度不足 3 时别硬开，否则 `head.next.next` 直接送你跳楼机体验。
