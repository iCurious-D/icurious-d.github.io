## 圆的每一寸弧，都在说别拆

上次 836 判两个矩形重叠，投影法降维——拍扁成 `x` 和 `y` 两个一维区间，各判各的，两行 `max/min` 收工。

今天矩形还是那个矩形，对面换了个圆。投影法还能故技重施吗？

------

#### 耦合：圆的本命

836 能降维，是因为矩形太“直”了：两个维度独立，`x` 和 `y` 各管各的，拆成两个一维区间分别判断，零信息损失。

圆不行。圆的定义本身就是一个 x 和 y 的联合约束: `(x - xc)² + (y - yc)² ≤ r²`，`x` 和 `y` 共享一个 `r²` 的预算——`x` 偏多了，`y` 就得收着。两个方向是耦合的，硬拆成两个独立的一维区间，就丢掉了"联合"这个关键信息。

一维区间表达不了弧形约束，`x` 和 `y` 不能独立判断——这正是圆和矩形的区别。

------

#### 直觉：最近的点

投影法走不通，换个方向。

圆是`到圆心距离 ≤ r`的点集。它有没有侵入矩形的领地，就看一件事：**矩形上离圆心最近的点，距离有没有 ≤ r**。

最近点在哪？看圆心相对矩形的位置：

- 圆心在矩形内或边界上：最近点就是圆心自己，距离 0。
- 圆心在矩形左边/右边，且 `y` 落在 `[y1, y2]` 内：最近点在对应的竖直边上，距离是水平差。
- 圆心在矩形上边/下边，且 `x` 落在 `[x1, x2]` 内：最近点在对应的水平边上，距离是垂直差。
- 圆心在某个角的外侧，即 `x` 和 `y` 都超出范围：最近点就是那个角，距离按勾股算。

四种情况，写四个 `if`？不急。

先看 `x` 方向：矩形上离 `xCenter` 最近的 `x` 坐标，只有一条逻辑——`xCenter` 小于 `x1` 就取 `x1`，大于 `x2` 就取 `x2`，在中间就取自己。这不就是把 `xCenter` 夹进 `[x1, x2]` 吗？

> `closest_x = max(x1, min(xCenter, x2))`

`min` 拦住右边界；`max` 拦住左边界。高了压，低了顶，中间不动。

`y` 方向同理：

> `closest_y = max(y1, min(yCenter, y2))`

两个 clamp 一合，四种情况全归一。

最近点有了，距离平方和 `r²` 一比——开不开根号无所谓，两边都是正数。

```python
def checkOverlap(radius: int, xCenter: int, yCenter: int, x1: int, y1: int, x2: int, y2: int) -> bool: 
    closest_x = max(x1, min(xCenter, x2))
    closest_y = max(y1, min(yCenter, y2))
    return (closest_x - xCenter) ** 2 + (closest_y - yCenter) ** 2 <= radius ** 2
```

O(1) 时间，O(1) 空间。两次 clamp，两次减法，收工。

------

#### 复盘

上次矩形重叠，**降维**——拆成两个一维，各判各的。

这次圆和矩形，**不能降维**——留在二维，找最近点，量距离。

毕竟，圆的每一寸弧，都是 `x` 和 `y` 共同写下的约定。
