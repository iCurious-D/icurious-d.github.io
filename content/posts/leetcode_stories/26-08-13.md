#### 任务简报

**悬赏令**：给你一根字符串 `s`，再来 `k` 次**单点修改**——每次把 `s[queryIndices[i]]` 换成 `queryCharacters[i]`。每次改完之后，立刻报出：**整根字符串里，由同一种字符组成的最长连续子串有多长？**

**数据规模**：`|s| <= 10^5`，`k <= 10^5`。

**示例怪物**：`s = "babacc"`, 修改序列 `"bcb"`, 下标 `[1, 3, 3]`

- 改完第 1 次：`"bbbacc"` → 最长 `"bbb"`，长度 **3**
- 改完第 2 次：`"bbbccc"` → 最长 `"bbb"` 或 `"ccc"`，长度 **3**
- 改完第 3 次：`"bbbbcc"` → 最长 `"bbbb"`，长度 **4**

输出 `[3, 3, 4]`。

（弹幕：10^5 长度 × 10^5 次查询，暴力遍历 × 生命加速器 √）
（弹幕：所以这题的核心是——每次只改一个字符，怎么**增量更新**答案？）
（弹幕：改一个字符，影响的只是它附近那一小片，跟整根字符串大部分区域没关系）

#### 零号选手·"我头铁我先上"暴力扫描流

一位浑身写着"我不信邪"的选手率先冲上台——他二话不说，撸起袖子就是一顿输出：

```python
def longestRepeating(s, queryCharacters, queryIndices):
    s = list(s)
    ans = []
    for pos, ch in zip(queryIndices, queryCharacters):
        s[pos] = ch                       
        # 暴力扫描最长连续段
        max_len = cur = 1
        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                cur += 1
                max_len = max(max_len, cur)
            else:
                cur = 1
        ans.append(max_len)
    return ans
```

#### 关键洞察：这 BOSS 的弱点在哪？

还记得开屏弹幕里那句“改一个字符，影响的只是它附近那一小片”吗？这就是命门。

（弹幕：局部性！关键字是局部性！）
（弹幕：我悟了，大部分区域压根不用重新统计，只在修改点附近动手就行）
（弹幕：所以暴力流 10^10 次运算，有效操作可能连 10^5 都不到，全在干无用功）

没错，把一个字符换掉，真正被影响的只有三小块：它所在的连续段、左邻段、右邻段。其他区域？看都不用看，该多长还多长。

抓住这个局部性，打法就清楚了——把字符串看成**一段段由相同字符组成的连续块**。每次修改，只拆合被波及的那几段；全局最长长度，交给一个“排行榜”实时维护。一次操作从 O(n) 直接砍到 O(log n)。

问题只剩一个——这个**"局部拆合 + 全局查最大"**，你打算用什么数据结构来扛？

今天两位正经选手，一个掏出了**SortedList** 搞区间管理，一个直接手搓**线段树**玩分治魔法。两种流派，同一个答案，但画风完全不同。

（弹幕：区间流：Python 黑科技，谁用谁知道）
（弹幕：线段树流：手搓大树，纯纯的硬核浪漫）

#### 一号选手·"区间管家"SortedList 流

一号选手缓步上台，他手里拎着两个 `SortedList`——一个存**区间坐标**，一个存**区间长度**。

“大家好，我的打法就四个字——**拆拆合合**。把字符串看成一条由同字符方块拼成的链条，每每次修改就是：**删旧段、拆残段、立新段、合邻居**。全程用 SortedList 保证有序，每次插入删除 O(log n)。”

```python
def longestRepeating(s, queryCharacters, queryIndices):
    n = len(s)
	s = list(s)
    segs = SortedList()   # 存连续段 (left, right)
    lens = SortedList()   # 存每段长度

    # 初始化：扫描字符串，切出所有同字符连续段
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        segs.add((i, j - 1))
        lens.add(j - i)
        i = j

    ans = []

    for pos, ch in zip(queryIndices, queryCharacters):
        if s[pos] == ch:          # 新字符和旧字符一样，没有变化
            ans.append(lens[-1])
            continue

        # 1. 删旧段：定位 pos 所在段，移除
        idx = segs.bisect_right((pos, n)) - 1
        L, R = segs[idx]
        segs.pop(idx)
        lens.remove(R - L + 1)

        # 2. 拆残段：旧段在 pos 处断开，左右残段（若有）插回
        if L <= pos - 1:
            segs.add((L, pos - 1))
            lens.add(pos - L)
        if pos + 1 <= R:
            segs.add((pos + 1, R))
            lens.add(R - pos)

       # 3. 新字符先单独成段
        newL = newR = pos

        # 4. 合并右邻：如果右边段字符与新字符相同
        if pos + 1 < n and s[pos + 1] == ch:
            idx = segs.bisect_left((pos + 1, -1))
            rightL, rightR = segs[idx]
            segs.pop(idx)
            lens.remove(rightR - rightL + 1)
            newR = rightR

        # 5. 合并左邻：如果左边段字符与新字符相同
        if pos > 0 and s[pos - 1] == ch:
            idx = segs.bisect_left((pos, -1)) - 1
            leftL, leftR = segs[idx]
            segs.pop(idx)
            lens.remove(leftR - leftL + 1)
            newL = leftL

        # 6. 插入新段，记录答案
        s[pos] = ch
        segs.add((newL, newR))
        lens.add(newR - newL + 1)        
        
        ans.append(lens[-1])     # 有序列表最后一个元素就是最大长度

	return ans
```

（弹幕：好家伙，Python 玩家直接掏出 `sortedcontainers` 外挂）
（弹幕：等等，`lens[-1]` 就是最大值？SortedList 自动维护有序？）
（弹幕：对！SortedList 内部是分块链表，插入删除 O(log n)，取最大 O(1)）

**老白解说**：一号选手的思路非常工程化，核心就是**只处理修改点附近的段**。每次修改分三步：

1. **定位旧段**：用 `bisect_right` 在 `segs` 里二分找到 `pos` 所在的段，把它从两个表里删掉。
2. **拆分残段**：旧段可能在 `pos` 两侧留下两个小段，分别插回。
3. **合并邻居**：新字符单独成段后，检查左右邻居是否同字符，是就合并，更新边界。

因为所有操作都在 `SortedList` 上完成，定位、插入、删除都是 O(log n)，所以总复杂度 **O(n + k log n)**，稳稳过 Hard。

（弹幕：所以每次修改最多拆一段、合两段、插一段，操作数是常数级别的）
（弹幕：SortedList 就是 Python 的瑞士军刀，谁用谁知道）
（弹幕：这代码看着长，其实逻辑就三件事：拆、合、报数）

（弹幕：区间管家，稳如老狗）
（弹幕：SortedList 真的是被低估的神器，内部实现插入删除 O(log n)）

#### 二号选手·"手搓大树"线段树流

一号刚坐下，二号选手就站了起来——他什么话都没说，直接在黑板上画了一棵二叉树：“SortedList？我不需要第三方库。我**自己搓一棵树**。”

（弹幕：？？？上来就画树，这是狠人）
（弹幕：线段树！我的噩梦！我的青春！我的面试必考题！）
（弹幕：手搓线段树，这才是算法竞技场的正确打开方式）

```python
class SegmentTree:
    def __init__(self, s: list[str]):
        self._n = n = len(s)
        self._s = s
        self._tree = [None] * (2 << (n - 1).bit_length())
        self._build(s, 1, 0, n - 1)

    def _combine(self, node, l, m, r):
        a_mx, a_pre, a_suf = self._tree[node * 2]
        b_mx, b_pre, b_suf = self._tree[node * 2 + 1]
        same = self._s[m] == self._s[m + 1]
        self._tree[node] = (
            max(a_mx, b_mx, a_suf + b_pre) if same else max(a_mx, b_mx),
            a_pre + b_pre if same and a_pre == m - l + 1 else a_pre,
            a_suf + b_suf if same and b_suf == r - m else b_suf
        )

    def _build(self, s, node, l, r):
        if l == r:
            self._tree[node] = (1, 1, 1)
            return
        m = (l + r) // 2
        self._build(s, node * 2, l, m)
        self._build(s, node * 2 + 1, m + 1, r)
        self._combine(node, l, m, r)

    def _update(self, node, l, r, i, val):
        if l == r:
            self._s[i] = val
            return
        m = (l + r) // 2
        if i <= m:
            self._update(node * 2, l, m, i, val)
        else:
            self._update(node * 2 + 1, m + 1, r, i, val)
        self._combine(node, l, m, r)

    def update(self, i, val):
        # 单点更新入口
        self._update(1, 0, self._n - 1, i, val)

    def query_all(self):
        # 根节点的 mx 就是全局最长连续相同字符段长度
        return self._tree[1][0]
    
    
def longestRepeating(s, queryCharacters, queryIndices):
    # 构建线段树
    t = SegmentTree(list(s))
    ans = []
    for i, ch in zip(queryIndices, queryCharacters):
        # 更新第 i 个字符
        t.update(i, ch)
        # 记录当前全局答案
        ans.append(t.query_all())
    return ans

```

（弹幕：每个节点存三个值？？mx、pre、suf 是什么鬼？）
（弹幕：等等，没有 query 函数？直接 `tree[1]` 就是答案？）

**老白解说**：别慌！这棵树看着复杂，核心逻辑拆开就三件事。

先说每个节点存的三元组 `(mx, pre, suf)` 分别是什么：

- **mx**：这个节点管辖区间内，最长同字符连续段有多长。
- **pre**：从区间左端点开始，最长同字符连续前缀有多长。
- **suf**：从区间右端点开始，最长同字符连续后缀有多长。

（弹幕：所以叶节点就是 (1,1,1)？一个字符，三个值都是 1）
（弹幕：父节点怎么合并两个子节点的信息？）

这就是整棵树最精华的部分——**合并操作 _combine**。来，导播把合并逻辑放大——

想象一个节点管着区间 `[0, 7]`，左孩子管 `[0, 3]`，右孩子管 `[4, 7]`。中间分界线在 `m=3` 和 `m+1=4` 之间。合并时只看一件事：**s[3] 和 s[4] 是否相等**。

**如果不相等（same = False）**——左右两半的连续段在边界处断开，各自独立：

- `mx = max(左.mx, 右.mx)`，最长段要么在左边，要么在右边，取大的。
- `pre = 左.pre`，前缀就是左孩子的前缀，跨不过去。
- `suf = 右.suf`，后缀就是右孩子的后缀，也跨不过去。

**如果相等（same = True）**——边界处打通了！左边的后缀和右边的前缀可以**连成一段**：

- `mx = max(左.mx, 右.mx, 左.suf + 右.pre)`，除了各自内部的最长段，还要考虑跨边界的这一段。

- 如果左孩子的**整个区间**都是同一个字符（`左.pre == m - l + 1`），前缀就能继续往右扩大：`pre = 左.pre + 右.pre`。否则左孩子中间就断了，前缀不变。
- 同理，右孩子的**整个区间**都是同色（`右.suf == r - m`），后缀才能往左扩大：`suf = 右.suf + 左.suf`。

（弹幕：懂了！pre 和 suf 就是为了跨边界合并而存在的！）
（弹幕：这设计太精妙了——每个节点不光存答案，还存了两个“接口”，方便与邻居对接）
（弹幕：所以 `tree[1]` 就是根节点，它的 mx 就是全局答案？）

**老白继续**：没错！根节点 `tree[1]` 的 `mx` 就是全局最长连续相同字符段。所以查询不需要单独函数——直接 `return self._tree[1][0]`，O(1) 白给。

修改呢？`update(i, val)` 从根节点往下找到叶子 `i`，改掉字符，然后**回溯时逐层重新合并**。每层合并就是一次 `_combine`，三个值的加减比较，O(1) 操作。树高 log n，所以单次修改 O(log n)。

k 次查询，总时间 O(n + k log n)。空间 O(n)，纯手搓，零依赖。

（弹幕：没有 `sortedcontainers` 依赖，面试能写）
（弹幕：线段树的 `_combine` 就是整个解法的灵魂——合并逻辑）
（弹幕：pre 和 suf 像拼图接口，字符相同就接上，不同就断开，优雅）

AC 图标，第二次亮起！

（弹幕：线段树流，硬核但干净）
（弹幕：这棵树的每个节点都像在说：我管我的地盘，提供接口朝外，随时准备合并）
