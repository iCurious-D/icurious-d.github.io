## 字符串 DP 全家桶：今天轮到 940

那位 HR 朋友今天又来了，消息更短，就俩字：“在吗？”

你回：“又裁？”

他甩来一个哭脸：“老板疯了。昨天好歹还给个目标 `t`，今天直接问：所有可能的精简方案里，有多少种**不一样**的结果？空公司不算。”

你：“数太大，还得对 `10^9+7` 取模。”

他：“……你怎么知道？”

你没回，你在翻昨天那篇题解的最后一行——“再加个去重 → 940”。

flag 这玩意，立了果然是要还的。

------

#### 一、难在哪？排列组合不行吗？

初看这题，每个字符留或不留，`2^n` 种组合，扣掉全删的 1 种，完事。

真这么简单，它就不会被标成 hard 了。

拿 `s = "aaa"` 试刀：留第一个 `a` 和第三个 `a`，结果是 `"aa"`；留第二个 `a` 和第三个 `a`，结果还是 `"aa"`

**长得一样，只能算一种。** 所以答案不是 7，而是 3：`"a"`、`"aa"`、`"aaa"`。

把 7 种全造出来，扔进 `set` 去重？内存条第一个跳出来罢工。`n` 能到 2000，`2^2000` 约等于 `10^602`，可观测宇宙的原子总数也才 `10^80`。枚举这条路，还没出发就被堵死了。

既然不能事后去重，那就得在计数的时候**自带去重**。怎么做到？换个维度看问题——

------

#### 二、换一本账：按“结尾是谁”分类

任何一份非空花名册，它**总有最后一个人**。这一点看似废话，却是破题的关键。

按“最后一个人是谁”来记账：

> `f[c]` = 以字符 `c` 结尾的**不同**子序列有多少个
> `total` = 所有 `f[c]` 的和，也就是当前所有不同非空子序列的总数

这个分法天然**不重不漏**：一份花名册只有一个结尾字符，不可能同时被两个字母认领。**分类标准本身就是去重**，不需要事后补救。

有了这个分类，接下来就可以从头过一遍名单，每遇到一个新员工 `c`，问一句：

> **这个新 c 能新开多少种以前没有的架构？**

所有用到新 `c` 的架构，一定是“某个旧架构 + `c`”的形式。旧架构可以是空，那就是光杆 `c` 自己。旧架构一共有 `total` 份，加上空，候选总数就是 `total + 1` 份。

但小心，**这些候选里，有些早就存在了**——旧架构 `(y + c)` 本身就以 `c` 结尾，那对于旧架构 `(y)`，它接上新 `c` ，得到的还是 `y + c`，没有创造任何新东西。这样的旧架构有多少？恰好是 `f[c]` 个，必须扣掉。

```python
new = (total + 1) - f[c]   # 所有旧架构+新c，扣掉已经以c结尾的旧账
f[c] += new                # 以 c 结尾的架构增加
total += new               # 总数增加
```

一句话：**新架构 = 光杆 c + 不以 c 结尾的旧架构接上 c**。旧的以 `c` 结尾的架构不参与，因为它们接上 `c` 只是把已有的架构再誊一遍，毫无创新。

```python
def distinctSubseqII(s: str) -> int:
    mod = 10**9 + 7
    f = [0] * 26          # f[c]：以字符 c 结尾的不同子序列个数
    total = 0             # 所有非空子序列的总数

    for ch in s:
        c = ord(ch) - ord('a')
        new = (total + 1 - f[c]) % mod   # 真正新增的架构数
        f[c] = (f[c] + new) % mod        # 更新以 c 结尾的架构数
        total = (total + new) % mod      # 更新总数

    return total

```

------

#### 三、增量式与覆盖式

上面那种‘先算 `new`，再加进 `f[c]` 和 `total`’的写法，叫**增量式**。下面这种省掉 `new` 的写法，叫**覆盖式**。

```python
def distinctSubseqII(s: str) -> int:
    mod = 10**9 + 7
    f = [0] * 26          # f[c]：以字符 c 结尾的不同子序列个数
    total = 0             # 所有非空子序列的总数

    for ch in s:
        c = ord(ch) - ord('a')
        others = total - f[c]   # 不以 c 结尾的数量，本轮不动
        f[c] = 1 + total        # 注意：是 = ，不是 +=
        total = (f[c] + others) % mod

    return total
```

数学上的覆盖式长这样：

> ```
> f[c]新 = f[c]旧 + new
>        = f[c]旧 + (total旧 - f[c]旧 + 1)
>        = total旧 + 1
> ```

旧的 `f[c]` 在化简里**自己消失了**。新值把旧值完整包含在内，所以直接覆盖就行，不是数据丢失，是合并完成。

`total` 同理：`total新 = others + f[c]新`，一步到位。

两种写法结果完全一样，覆盖式就是增量式的压缩版。面试时先写增量式保命，聊嗨了再甩覆盖式展示内功。

无论用哪种写法，复杂度都一样：时间 `O(n)`，扫一遍名单；空间 `O(26)` 即 `O(1)`。

昨天 `O(m × n)` 的记忆化搜索表，今天压成一条 26 格的数组——**分类维度选对了，状态只剩一维，连递归都省了**。

------

#### 彩蛋：昨天立的 flag，今天拔了

昨天那份家族清单：

> - 加法数方案 → **115 不同的子序列**
> - 换成 `max` 求最长 → 1143 最长公共子序列
> - 换成 `min` 求最少删 → 583 两个字符串的删除操作
> - 再加个去重 → **940 不同的子序列 II**

115 的问题是“**你留不留**”，940 的问题是“**你留了之后，跟别人一样吗**”。

下次再遇到字符串 DP，别急着写 `set`。分类维度选对了，去重就是顺手的事。
