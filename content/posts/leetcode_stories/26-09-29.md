## 物理入栈，记忆化递归：@cache 救我狗命

昨天你还笑 Lisp 程序员一辈子困在括号森林里，今天力扣就把你空投了进去。

一张 `m × n` 的网格，每格不是 `(` 就是 `)`。你从左上角出生，只能向下或向右，目标是右下角的出口。而唯一活着出去的通行证是——一路踩过的括号，必须连成一个合法括号串。

不能回头，不能读档，走错一步就暴毙。

那么，你的蛇皮走位，能杀出这片森林吗？

------

#### 一、开局三刀

别急着 DFS 撒腿狂奔。有三类局，开局就跪，先一刀砍掉，省得递归白跑：

**第一刀：路径长度必须是偶数。**

合法括号串永远成双成对，长度必为偶数。从左上角走到右下角，一共踩 `m + n - 1` 个格子——这个数是偶数，`m + n` 就得是奇数：`(m + n) % 2 == 0` 的直接抬走。

**第二刀：起点必须是 `(`。**

`grid[0][0] == ')'` ，相当于出生点埋了雷，第一步就炸。

**第三刀：终点必须是 `)`。**

出口杵着个 `(`，就像跑完马拉松发现终点线是堵墙——卡死。

三刀合并，一行送走：

```python
m, n = len(grid), len(grid[0])
if (m + n) % 2 == 0 or grid[0][0] == ')' or grid[m - 1][n - 1] == '(':
    return False
```

能扛过这三刀的森林，才有资格见证你真正的走位实力。

------

#### 二、DFS 闯关

三刀砍完，正式开跑。

从 `(0,0)` 出发，每踏进一个格子，面对的都是同一道人生选择题：向下，还是向右？

但不管你怎么走位，背包不能丢，里面装的是你一路走来**还没配对的左括号**，数量记作 `k`：

- 踩到 `(`：捡到一个左括号，塞进背包，`k += 1`。
- 踩到 `)`：从背包里掏出一个左括号和它抵消，`k -= 1`。
- 如果 `k < 0`：背包已经倒欠了还想掏？等于无中生有——这条路当场作废。
- 摸到终点时，背包必须正好清空（`k == 0`）：还剩左括号（`k > 0`）？烂尾工程，不收。至于 `k < 0`？右括号超前消费，半路就被砍了，压根走不到终点。

起点 `(0,0)` 已经在脚下了，前面三刀保证了它一定是 `(`，所以你是带着一个左括号上路的——初始状态：`dfs(0, 0, 1)`。

递归每踏进一个格子，都会替未来的自己问一句：

> "我此刻站在 `(i, j)` 上，背包里有 `k` 个左括号，从这里到出口，有没有活路？"

`100 × 100` 的森林，近 200 步的岔路。要是每个格子都刨根问底，路径总数直接指数爆炸。

不过好在**江湖不问来路，递归只认状态。**你打哪儿来，那是你的故事；你当下的 `(i, j, k)`，才决定你的命数。

只要你站在同一个`(i, j)`上，背包里装着同样多的 `k` 个左括号，那么不管你是绕了个大弯摸过来的、还是一路直冲冲过来的，接下来能走的路，**一模一样**。

同一个状态，同一个结局。把 `(i, j, k)` 丢给 `@cache`，问过的直接抄答案。指数级当场塌成多项式。

```python
@cache
def dfs(i: int, j: int, k: int) -> bool:
    if i == m - 1 and j == n - 1:
        return k == 0
    if k < 0:
        return False
    return (i < m - 1 and dfs(i + 1, j, k + 1 if grid[i + 1][j] == '(' else k - 1)) or \
        (j < n - 1 and dfs(i, j + 1, k + 1 if grid[i][j + 1] == '(' else k - 1))

return dfs(0, 0, 1)
```

时间复杂度：`O(m * n * (m + n))`，背包最大也就 `m + n` 个左括号。
空间复杂度：`O(m * n * (m + n))`，主要是缓存和递归栈的开销。

今天 2267，每往下递归一格，调用栈就实打实压上一层 `dfs(i, j, k)`。那个 `k` 还是昨天的老熟人——没配对的左括号数；只不过昨天你用一个 `int` 脑补它，今天背后真有一整个栈替你扛。

好在这森林最深就 `m + n - 1` 层，递归撑死 199 层，Python 默认的一千额度绰绰有余，还轮不到你表演栈溢出。
