## 赛博教室之BFS 影分身：能量条不够，分身来凑

欢迎来到力扣 3568 的赛博教室。

你是一个能量条短得令人落泪的扫地机器人，面前是一张 `m x n` 网格：

- `'S'`：你的出生点；
- `'L'`：垃圾，必须捡；
- `'R'`：充电桩，踩上去能量瞬间拉满；
- `'X'`：空气墙别撞，绕道走；
- `'.'`：空地，啥也没有。

每移动一格，掉 1 点能量，能量掉到 0 且此刻没在 `'R'` 上，直接黑屏宕机。  

你的目标只有一个：**用最少的步数，捡完所有垃圾。**

------

#### 直线最短？能量条教你做人

你站在起点，环顾四周。如果能量无限，这就是个普通的网格最短路。  

但现在能量条短得跟蚊子血似的，闷头硬冲的后果大概率是：

> 走到一半，能量见底，前不着垃圾，后不着充电桩，只能仰天长叹：“早知道绕一下了……”

能量限制让“走哪条路”变成了一个生存策略问题：贪心不行——你分不清哪个方向"更值"；DFS 也不行——一条道走到黑，能量耗尽才发现此路不通，连回头的电都没了。

于是你冷静下来，盘了盘局势：

- 目标是**最少移动次数**；
- 每一步代价都是 **1**；
- 地图上所有可走格子构成一张**无权图**。

经典的**无权图最短路**问题。解决它的标配，正是 BFS。

------

#### **影分身之术：BFS 逐层扩散**

BFS 的精髓是**逐层扩散**：第 0 层是起点，第 1 层是所有走 1 步能到的位置，第 2 层是所有走 2 步能到的位置……像水面波纹一样向外推。

你只要同时派出多个分身（别问扫地机器人怎么分身，问就是影分身之术），在同一层内同步探索所有可能的方向。如果某条路走 3 步就捡完所有垃圾，答案就是 3；不可能存在另一条路只走 2 步却更晚被发现——因为 2 步能到的位置在第 2 层就全部探过了。

这就是 BFS 的铁律：**无权图上，先到即最优**。

------

#### 分身装备：“三件套” 和 背包压缩

既然用 BFS，每个分身出发前都得背好三样东西：

- **坐标** `(r, c)`—— 我在哪
- **背包** `mask`—— 捡了哪些垃圾
- **能量** `eng`—— 还能走几步

位置好说， 能量也好说，都是整数。  问题出在“背包”——怎么存“哪些垃圾已经捡过”？

垃圾最多 10 个，每个垃圾只有两种状态：捡了 / 没捡：正好对应二进制的 10 个 bit。

用一个整数 `mask` 的低 10 位表示背包：

- 第 `i` 位为 1：第 `i` 个垃圾已经入包；
- 全亮：`mask == (1 << L) - 1`，也就是 1023，通关。

一个整数搞定全部收集进度，掩码一扫，背包进度一目了然——别人翻包找道具，你直接读 bit。

把三件套打包成一个状态 `(r, c, mask, eng)`，BFS 要干的事就一句话：

**从起点出发，逐层向外扩散，每多走一步就多一层，第一次出现“背包全亮”的步数就是答案。**

------

#### 状态剪枝：低能量分身，原地出局

状态三件套是打包好了，但你掐指一算，发现一个可怕的事实：

位置最多 `m × n` 个，背包最多 `2^L` 种，能量最多 `E` 档——三维一乘，状态数直接起飞。

分身越派越多，你很快注意到一个内卷惨案：

> 两个分身到了同一个格子，背包进度一模一样，
> 一个剩余能量 5，一个剩余能量 2。
> 能量 2 的那位，可以直接出局了。

凭什么？能量 5 完全支配能量 2，低能量版本没有任何翻身的可能——它之后能走的所有路，能量 5 都能走，甚至还能多走几步——典型的**状态支配**：如果状态 A 在所有维度上都不劣于状态 B，那么 B 就可以被安全淘汰。

于是你再整个小本本 `best`，记录每个 `(位置, 背包)` 组合见过的**最大剩余能量**。

新分身如果能量不超过已有记录，直接淘汰，连入队的资格都没有。

有了这层剪枝，能量维度实际上被吞掉了——`best` 只存每个 `(位置, 背包)` 的最优能量值，状态数从 `位置 × 背包 × 能量` 直接降到 `位置 × 背包`，也就是 `m × n × 2^L`。

**同状态只留最强打工人，其余全部内卷出局。**

------

#### 移动结算：踩一格，算一格

一切准备就绪，你深吸一口气，开始从起点逐层扩展。

每个分身每迈一步，都要走一遍标准的“踩格子结算流程”：

1. **先扣 1 点**：走一步掉一格电，天经地义。
2. **看看脚下**：
   - **出界 / 撞 `'X'`**—— 空气墙，此路不通，分身当场掉头（其实连格子都没进去）。
   - **踩到 `'R'`**—— 充电桩！能量瞬间回满，你长舒一口气：“还好有续命插座。”
   - **踩到 `'L'`**—— 垃圾入包，对应二进制位点亮，`mask` 又丰满一格。
   - **啥也没有`.`**—— 无事发生，继续赶路。
3. **检查通关**：mask 全亮了？别犹豫，直接 return 当前步数。BFS 逐层扩展，**第一个摸到"全亮"的步数就是全局最优**，后面的层都不用看了。
4. **检查能量**：扣完能量后若是 0，且当前格子不是 `'R'` → 寄，该分身从队列中移除（能量归零时只有踩在 `'R'` 上才能续命回满）。
5. **查小本本**：每个新状态入队前，先查 `best` 小本本：如果同位置同背包已有更高能量，那这个弱鸡分身就别浪费队列空间了。

注意，结算顺序很关键：第 3 步必须在第 4 步之前。 如果你先判能量再结算效果，就会在能量归零的那一刻错过 'R' 的续命和 'L' 的收集——死在终点线上，冤不冤？

------

```python
class Solution:
    def minMoves(self, classroom: list[str], energy: int) -> int:
        m, n = len(classroom), len(classroom[0])
        
        sr = sc = -1
        garbage = []
        
        # 先扫一遍地图：找到起点和所有垃圾
        for i in range(m):
            for j in range(n):
                if classroom[i][j] == 'S':
                    sr, sc = i, j
                elif classroom[i][j] == 'L':
                    garbage.append((i, j))
        
        L = len(garbage)
        if L == 0:
            return 0  # 没有垃圾，直接下班
        
        # 给每个垃圾编号，方便位运算
        garbage_id = {(r, c): i for i, (r, c) in enumerate(garbage)}
        full_mask = (1 << L) - 1  # 全亮 = 1023，通关
        
        # BFS 队列：(行, 列, 背包, 能量, 步数)
        queue = deque([(sr, sc, 0, energy, 0)])
        
        # 内卷小本本：(位置, 背包) → 最大能量
        best = {(sr, sc, 0): energy}
        
        directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
        
        while queue:
            r, c, mask, eng, steps = queue.popleft()
            
            # 过期分身：已经被更强的同状态取代
            if best.get((r, c, mask), -1) > eng:
                continue
            
            for dr, dc in directions:
                nr, nc = r + dr, c + dc
                
                # 出界或撞墙
                if not (0 <= nr < m and 0 <= nc < n):
                    continue
                if classroom[nr][nc] == 'X':
                    continue
                
                # 移动消耗 1 点能量
                neng = eng - 1
                if neng < 0:
                    continue  # 没电了，出局
                
                # 充电桩回满
                if classroom[nr][nc] == 'R':
                    neng = energy
                
                # 垃圾入包
                nmask = mask
                if (nr, nc) in garbage_id:
                    nmask |= (1 << garbage_id[(nr, nc)])
                
                # 垃圾全捡完了，返回最少步数
                if nmask == full_mask:
                    return steps + 1
                
                # 能量归零且不在 R：不能继续移动
                if neng == 0:
                    continue
                
                # 查小本本
                key = (nr, nc, nmask)
                if neng > best.get(key, -1):
                    best[key] = neng
                    queue.append((nr, nc, nmask, neng, steps + 1))
        
        return -1  # 队列清空仍未通关，无解
```

理论上三维 BFS 的状态数是： `O(m × n × 2^L × E)`，其中 `E` 是能量上限。但 `best` 剪枝会把能量维度大幅压缩——同一个 `(位置, 背包)` 只保留最大能量，低能量分身全部淘汰。在 `L ≤ 10` 的约束下，实际跑的状态数远小于理论上限。

------

#### 尾声

你终于走出了这间赛博教室，能量条刚好停在 `1%`，不多不少，够你回充电桩鞠个躬。

回头看了一眼，满地图的垃圾已经被捡得干干净净，连一点渣都不剩。

谁能想到，一条能量条短得像蚊子血的扫地机器人，靠着 **BFS 影分身**、**bitmask 收纳术** 和 **内卷剪枝**，硬是走出了最优解。

所以说，能量少不是问题，路线骚才是关键。
