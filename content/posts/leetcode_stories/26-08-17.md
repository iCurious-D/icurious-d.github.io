## **MC劈石考验：暴力递归的救赎之路**

#### 开局

上次从末地回来，我做了一个决定：把 Bob 的 Discord 通知设为免打扰。

坚持了整整 23 小时。

凌晨三点，手机屏幕亮了。不是 Discord——是游戏里直接弹的传送邀请。邀请人一栏写着个"末"字，备注：你设了免打扰，但没设传送屏蔽。

好家伙，末影人学会绕道了。

我点了接受。眼前一紫，人已经站在熟悉的紫色基岩平台上。末地石还是那个末地石，末影龙在远处绕圈还是那个绕圈。但平台中央这次没摆石子——取而代之的是一长条发光的石板，每块上面刻着数字，像极了服务器机房里跑飞的 LED 灯带。

Bob 还是那副漆黑修长的末影人身板，紫色眼睛亮度调到了 90%——又高了 10 个百分点，看来是充了 VIP。

脚边新告示牌：

> **劈石取半**
> n 块石板排成一行，每块刻着一个数字。
> 每一轮：你 把石板劈成两半（都非空）。
> 算两半的总和，Bob 丢掉大的那半。你拿小的那半的总和作为得分。
> 两半相等？你选丢哪半。

Bob 举起一块牌子：

他顿了顿，又举起一块：

#### 第一刀：区间 DP——看起来很美

行吧，没有取巧的余地，那就老老实实建模。

这次游戏的核心结构是**区间**——每次劈完，剩下的还是连续的一段。换句话说，切完之后，问题只是在一个更短的连续区间上继续做同样的事情，这不就是递归子问题吗？

直接定义递归函数：

> `dfs(i, j)` = 在石板区间 `[i, j)` 上，我 能拿到的最大分数。

边界很直接：如果区间只剩一块（`j - i == 1`），没得劈，当前这轮得分 0，游戏结束。

否则，我需要在区间里选一个位置 `k`，把 `[i, j)` 劈成左右两段：`[i, k)` 和 `[k, j)`。关键来了——Bob 会丢掉两段中总和更大的那段，我拿剩下的那段作为本轮得分，下一轮再在剩下的那段上继续劈。

每试一个 `k`，我得先知道左右两段的总和——先把整段石板的价值跑一遍前缀和，存成数组 `s`。这样不管切在哪，左右总和都能 O(1) 拿到：`sum_l = s[k] - s[i]`，`sum_r = s[j] - s[k]`

有了左右总和，剩下的判断就简单了：

- `sum_l < sum_r`：Bob 丢右边，我拿 `sum_l`，下一轮在左半继续 → 总分 `sum_l + dfs(i, k)`
- `sum_l > sum_r`：Bob 丢左边，我拿 `sum_r`，下一轮在右半继续 → 总分 `sum_r + dfs(k, j)`
- `sum_l == sum_r`：Bob 让我选丢哪半。我当然要留下后续得分更高的那边 → 总分 `sum_l + max(dfs(i, k), dfs(k, j))`

把所有切点枚举一遍，取最大值就是 `dfs(i, j)` 的答案。

```python
s = list(accumulate(stoneValue, initial=0))

@cache
def dfs(i, j):
    if j - i == 1:
        return 0
    res = 0
    for k in range(i + 1, j):
        sum_l = s[k] - s[i]
        sum_r = s[j] - s[k]
        if sum_l < sum_r:
            score = sum_l + dfs(i, k)
        elif sum_l > sum_r:
            score = sum_r + dfs(k, j)
        else:
            score = sum_l + max(dfs(i, k), dfs(k, j))
        res = max(res, score)
    return res
```

状态 O(n²)，每个状态枚举 O(n) 个切点，总复杂度 **O(n³)**。n = 500，1.25 亿次操作。

Bob 在旁边看着我，紫色眼睛的亮度缓缓降到了 30%。那个亮度我认识——**末影人的"你完了"表情**。

果然，他又举起一块牌子：

> "O(n³) 跑完，末影龙都能把鳞片数三遍了。"

#### 第二刀：谁在白打工？

问题出在哪？拿 `[6,2,3,4,5,5]` 举个栗子，总和是 25，把所有切点枚举出来：

```
k=1: [6]          | [2,3,4,5,5]   sum_l=6,  sum_r=19  → 拿 6
k=2: [6,2]        | [3,4,5,5]     sum_l=8,  sum_r=17  → 拿 8
k=3: [6,2,3]      | [4,5,5]       sum_l=11, sum_r=14  → 拿 11  ★ 平衡区
k=4: [6,2,3,4]    | [5,5]         sum_l=15, sum_r=10  → 拿 10
k=5: [6,2,3,4,5]  | [5]           sum_l=20, sum_r=5   → 拿 5   ← 白打工
```

靠近平衡点的 k=3，左右差不多，我能拿 11，几乎是总和的一半；越往两端，能拿的就越少，到了 k=5 只能拿 5。哪怕后面在 `[5]` 上继续切，最多也只能再拿 5，总得分 10，连 k=3 的本轮得分都追不上。

所以这些远离平衡点的切点，从出生起就是来陪跑的。

更一般地，任意切点下，我本轮拿的一定是 `min(sum_l, sum_r)`，记作 `m`。下一轮只能在剩下那段（价值也是 `m`）上继续，所以后续得分最多不超过 `m`。所以每个切点的总得分上限就是：`m + m = 2m`。

如果我已经有了当前最优 `res`，只要 `2m <= res`，这个切点就永远不可能超过 `res`，可以直接放弃。

最关键的是：**离平衡点越远，左右两边越不平衡，m 就越小。** 所以一旦某个切点满足 `2m <= res`，它**外侧的那些切点只会更小**，更没希望，全部可以直接剪枝。

我蹲下来在基岩上画了张图：

```
得分上限
    ▲
    │        ★ ★
    │      ★     ★
    │    ★         ★
    │  ★             ★
    │★                 ★
    └──────────────────────→ k
    k=1               k=5
              ↑ 平衡点
```

越往两端走，两边越不平衡，`m`越来越小。“这不就是切西瓜？”我敲了敲基岩，“刀越偏，小瓣越小。你只能拿小瓣，那自然是越偏越亏，偏到最后连塞牙缝都不够。”

核心洞察浮出水面：

> **每个切点的得分上限是 `2 × min(sum_l, sum_r)`。一旦这个上限不超过当前最优 `res`，切点作废；又因为离平衡点越远 `min` 越小，所以从该点往外，所有切点都可以一并剪掉。**

#### 第三刀：二分定位 + 双向剪枝

知道了"越偏越废"，那现在的问题就变成两件事，对于区间`[i, j)`：

1. 怎么快速找到平衡点？
2. 怎么从平衡点出发，高效地向两边扫，遇到没戏的立刻停？

先解决第一个问题：**定位平衡点**。

说白了，要找的就是让左右两半尽量对半分的位置。好在一开始我们有前缀和数组 `s` ，它单调递增，天生适合二分查找。

`total = s[j] - s[i]` 是当前区间的总和，`(total + 1) // 2` 是“总和的一半(向上取整)”，`s[i] + (total + 1) // 2` 就是“左半和刚好到一半时对应的前缀和值”——用 `bisect_left` 找第一个 `>=` 这个值的位置 `p`，那 `p-1` 就是最后一个左半和小于一半的切点，也就是左右最平衡的位置。最后夹一下范围防止二分结果越界。

```python
total = s[j] - s[i]
k = bisect_left(s, s[i] + (total + 1) // 2, i + 1, j + 1) - 1
k = max(i, min(k, j - 1))  # 防止二分结果越界，把 k 夹回合法切点范围 [i, j-1]。
```

**找到 `k` 之后，从它开始向两边扫。**

**向右扫**：切点越靠右，右半和 `sum_r` 越小，本轮拿的是 `sum_r`。总分上限 `2 * sum_r` 也随之变小，一旦小到不超过当前最优 `res`，后面只会更小，直接 break。

```python
m = k
while m < j:
    sum_l = s[m + 1] - s[i]
    sum_r = s[j] - s[m + 1]
    if 2 * sum_r <= res:    # 右半太小，后面更没戏
        break
    # ... 正常转移
    m += 1
```

**向左扫**：切点越靠左，左半和 `sum_l` 越小，本轮拿的是 `sum_l`，同理当 `2 * sum_l <= res` 时停止。

```python
m = k - 1
while m >= i:
    sum_l = s[m + 1] - s[i]
    sum_r = s[j] - s[m + 1]
    if 2 * sum_l <= res:    # 左半太小，收工
        break
    # ... 正常转移
    m -= 1
```

两把剪刀一夹，实际搜索的分割点从 O(n) 骤降到 O(1)~O(log n)，效果立竿见影。

把三件套拼起来——记忆化 + 二分定位 + 双向剪枝：

```python
def stoneGameV(stoneValue: List[int]) -> int:
    s = list(accumulate(stoneValue, initial=0))

    @cache
    def dfs(i: int, j: int) -> int:
        if j - i == 1:            # 只剩一块，游戏结束
            return 0

        total = s[j] - s[i]
        res = 0

        # 二分定位：找最平衡的分割点
        k = bisect_left(s, s[i] + (total + 1) // 2, i + 1, j + 1) - 1
        k = max(i, min(k, j - 1))

        # 向右扫：sum_r 递减，小到没戏就收兵
        m = k
        while m < j:
            sum_l = s[m + 1] - s[i]
            sum_r = s[j] - s[m + 1]
            if 2 * sum_r <= res:
                break
            if sum_l < sum_r:
                score = sum_l + dfs(i, m + 1)
            elif sum_l > sum_r:
                score = sum_r + dfs(m + 1, j)
            else:
                score = sum_l + max(dfs(i, m + 1), dfs(m + 1, j))
            res = max(res, score)
            m += 1

        # 向左扫：sum_l 递减，小到没戏就收兵
        m = k - 1
        while m >= i:
            sum_l = s[m + 1] - s[i]
            sum_r = s[j] - s[m + 1]
            if 2 * sum_l <= res:
                break
            if sum_l < sum_r:
                score = sum_l + dfs(i, m + 1)
            elif sum_l > sum_r:
                score = sum_r + dfs(m + 1, j)
            else:
                score = sum_l + max(dfs(i, m + 1), dfs(m + 1, j))
            res = max(res, score)
            m -= 1

        return res

    return dfs(0, len(stoneValue))
```
