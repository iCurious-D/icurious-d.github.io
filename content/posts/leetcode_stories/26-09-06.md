## 老板要精简架构，我掏出了递归

你的朋友是HR，深夜发来一条消息，只有三个字：“救救我。”

你问：“怎么了？又有人仲裁？”

他甩过来一串名单：`s = "rabbbit"`，紧接着补了一句：“老板说公司要精简，目标组织架构是 `t = "rabbit"`。我数了一下，就裁一个人。可公司有**三个一模一样的** `b`，裁谁结果都一样。你说，这算几种裁法？”

你沉默了三秒，回他：“从 `s` 里删掉一些字符，让剩下的正好是 `t`，问有几种删法——这不就是力扣 115 吗？在 s 的子序列中统计 t 出现的个数。”

他秒回了个“对对对”，然后问：“所以到底怎么算？”

你盯着屏幕，敲回去一行字：“**站到名单最后一个人面前，问他一句：你，留不留？**”

------

#### 一、从最后一个字符开始灵魂拷问

"在 s 的子序列中统计 t 出现的个数"——注意，子序列不是子串，子串必须连续，子序列**可以跳着挑**。

既然子序列可以跳着挑，那换个角度看：从 s 里选一些字符保留，等价于**从 s 里删掉一些字符，让剩下的正好是 `t`**。保留和删除是一体两面：你选哪些留，就等于决定哪些走。方案数完全一样，但“删”更直观——你不用管最后剩下谁，只要数哪些位置可以扔。

所以，站到字符串 `s` 的最后一个字符上，比如 `"rabbbit"` 的最后一个 `t`，问它一句：

> **"兄弟，你留不留？"**

它只有两条路可走：

- **被裁掉**——滚蛋，问题缩小为：`s` 少一个字符，`t` 不变。
- **留下来**——那它必须正好能顶 `t` 的最后一个位置，也就是就是 `s[i] == t[j]`。顶上了之后，问题缩小为：`s` 少一个字符，`t` 也少一个字符。

这两条路**互斥**——一个字符不可能既滚蛋又留下；同时**穷尽**——要么滚蛋要么留下，没有第三选择。所以方案数就是：**两种情况加起来**。

这就是**加法原理**，简单到像你妈问你“吃不吃鸡蛋”：吃是一种，不吃是另一种，没有第三种可能。

------

#### 二、把拷问写成一个递归函数

单个字符的“留不留”搞清楚了。但名单上一串字符，不能只问最后一个，得**从后往前挨个问过去**——因为每次问完一个，问题就缩小成‘前面那些人怎么凑剩下的岗位’，正好是**递归**的子问题。

定义函数 `dfs(i, j)`：

> **用 s[0..i] 这些字符，凑出 t[0..j] 这些字符，有几种方案？**

把上面那套“留不留”的决策逻辑翻译成递归，就三行：

```python
# 情况一：s[i] 不留，让前面的人自己想办法，问题缩小为 dfs(i-1, j)
res = dfs(i - 1, j)

# 情况二：如果 s[i] 能留（s[i] == t[j]），就加上留它的方案数
if s[i] == t[j]:
    res += dfs(i - 1, j - 1)
```

不留的情况 + 留的情况，互斥且穷尽，一个不多一个不少，加起来就是完整答案。

------

#### 三、边界条件——递归的“刹车片”

递归不能一直套娃，得有个头。

- **`j < 0`**：`j` 掉到 -1，说明 `t` 已经全凑好了，目标架构已经达成。`s` 剩下的字符怎么办？**全部删掉，得到空串**。空串是任何字符串的子序列，而且只有这一种凑法，所以返回 `1`。
- **`i < j`**：说明 `s` 剩下的字符**根本不够**凑出 `t` 剩下的部分，巧妇难为无米之炊，直接返回 `0`。就像公司只剩 3 个人，却要填 5 个岗，门都没有。

两个边界 `return` 谁写前面都行。因为当 `j` 降到 -1 时，`i` 至少也是 -1，此时 `i < j` 不可能成立。

------

```python
def numDistinct(s: str, t: str) -> int:
    @cache
    def dfs(i, j):
        if i < j:          # 字符不够，没法凑
            return 0
        if j < 0:          # 目标完成，空串收工
            return 1

        res = dfs(i - 1, j)               # 情况1：不留 s[i]
        if s[i] == t[j]:                  # 情况2：s[i] 能留（==t[j]）
            res += dfs(i - 1, j - 1)
        return res

    return dfs(len(s) - 1, len(t) - 1)
```

 `@cache`是 Python 的**记忆化神器**，不加是指数级的递归树，加了塌成多项式：每个状态只算一次，快得飞起。

时间复杂度：`O(m × n)`，空间复杂度：`O(m × n)`。如果面试官逼你优化空间，可以改成自底向上的 DP，甚至压缩成一维数组。但把这个递归版本讲清楚，已经能拿下九成的面试了。

------

#### 彩蛋：换个运算符，就是另一道题

别急着划走。这套“最后一个字符留不留”的骨架，换个合并方式就能通吃一整族题：

- 加法数方案 → 本题 115
- 换成 `max` 求最长（相等时再 +1）→ 1143 最长公共子序列
- 换成 `min` 求最少删 → 583 两个字符串的删除操作
- 再加个去重 → 940 不同的子序列 II

同一个递归骨架，换换运算符，直接刷穿字符串 DP 全家桶。
