## 一个字符的微更新：找到那个改变结局的存档点

> 给你一堆字母（`s`），排个序，刚好比 `target` 大一点。

"**刚好大一点**"——这五个字就是整道题的全部。不是最大，不是随便大，是**最小的大**。

就像发版从 `v1.0.0` 升到 `v1.0.1`，绝不直接跳 `v2.0.0`。追求的是“我确实更新了，哪怕只是往前挪了一小步”。

------

#### 核心洞察：答案长什么样？

不急着写代码，先想答案的结构。

你要的是一个排列 `ans` > `target`，且 `ans` 尽可能小。那 `ans` 一定长这样：

> ```
> target[0..i-1]  |  某个 > target[i] 的字符  |  剩余字符升序
>     完全打平          在这个断点上反超           后面躺平最小化
> ```

即"**尽量长的匹配前缀 + 一个恰到好处的断点 + 后面躺平最小化**"。

为什么？因为字典序比较是从左往右的，**前面跟 `target` 一样**才能让"反超"发生在尽可能靠后的位置，这样整体最接近原版，改动也最小；**断点`i`那一位放刚好大于 `target[i]` 的字符**，赢一块钱的就行；既然已经赢了，后面自然能多小就多小，躺平最小化就行了。

所以问题变成两件事：

1. 断点 `i` 选哪？ 越靠右越好。
2. 前缀 `target[0..i-1]` 能不能凑出来？ `s` 的字符够不够用？

------

#### 从左到右，逐位决策

最直觉的做法：从左到右一位一位填。

- 能填 `target[i]` 就填——打平，继续往下看（后面可能走不通）。
- 填不了 `target[i]` ，就填**比它大**的**最小字符**——赢了，后面升序收工。
- 两个都填不了？走不通，回溯：上一位换个更大的试试

走一步看一步，走不通就回头。就像打游戏时反复读档：先选个普通选项，发现后面坏结局了，立刻读档回来选个更激进的选项。不过好在只有 26 个字母，不至于把存档点刷烂。

```python
def lexGreaterPermutation(s: str, target: str) -> str:
    n = len(s)
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1
    path = []

    def fill_remaining():
        # 把剩余字符拼起来——你已经赢了，后面怎么小怎么来
        res = []
        for c in range(26):
            if cnt[c] > 0:
                res.append(chr(c + 97) * cnt[c])
        return ''.join(res)

    def backtrack(i):
        if i == n:
            # 全打平 = 等于 target，没严格大于，白忙一场
            return ""  

        for c in range(26):
            if cnt[c] == 0 or c < ord(target[i]) - 97:
                continue
            # 选了 c
            cnt[c] -= 1
            path.append(chr(c + 97))

            if c > ord(target[i]) - 97:
                # 当前位直接反超！后面躺平，收工
                return ''.join(path) + fill_remaining() 
            else:
                # 打平，暂时安全，继续看下一位
                res = backtrack(i + 1)
                if res != "":
                    return res  # 后续走通了，整条链路 OK
			
            # 回溯：这个 c 不靠谱，拿掉，换更大的
            path.pop()
            cnt[c] += 1 

        return ""  # 当前位置无论放什么都无法最终超过 target，回溯

    return backtrack(0)
```

回溯核心就三句话：**打平就深入，赢了就收工，都不行就回退。**

 听起来很干脆，但实际上每一步都在“苟一下”和“冲一下”之间反复仰卧起坐——能不能省掉这些试探，直接找到反超点？

------

#### 从右到左，一步到位

回顾下答案的结构：一长段和 target 一模一样的前缀 + 一个刚好更大的字符 + 后面升序躺平。

断点越靠右，前缀越长，字典序就越小——所以最优解就是**最靠右的那个断点**。

也就是说，直接从右往左找，找到的第一个可行位置，就是答案。

具体地，从最后一个位置开始往前看，对于位置 `i`：

- 先检查前缀 `target[0..i-1]` 能不能用 `s` 里的字符凑出来。
  - 凑不出 → 这个 `i` 没戏，继续往左。
- 前缀凑得出，再看剩余字符里有没有一个刚好大于 `target[i]` 的字符。
  - 有 → 断点成立，构造答案，收工。
  - 没有 → 断点不成立，继续往左。

怎么判断前缀能不能凑出来？维护两个计数数组：

- `cnt`：`s` 中每个字符的仓库库存，全程不变。
- `pre`：初始是整个 `target` 的字符计数；从右往左每移动一位，就减去当前 `target[i]` 的计数，剩下的就是前缀 `target[0..i-1]` 的需求。
- 如果某个字符 `c` 满足 `pre[c] > cnt[c]`，说明库存不够凑这个前缀，直接跳过。

**一遍扫描，零回溯**。这就像开二周目带着攻略，直接从结局倒回最后那个还能改变结局的分歧点，改完就躺赢。

```python
def lexGreaterPermutation(s: str, target: str) -> str:
    n = len(s)
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    pre = [0] * 26
    for ch in target:
        pre[ord(ch) - 97] += 1

    for i in range(n - 1, -1, -1):
        ti = ord(target[i]) - 97
        pre[ti] -= 1  # target[i] 不再属于前缀

        if any(pre[c] > cnt[c] for c in range(26)):
            continue  # 库存不够凑前缀，这个 i 没戏

        # 在剩余字符里找 > target[i] 的最小字符
        use = -1
        for c in range(ti + 1, 26):
            if cnt[c] - pre[c] > 0:  # s 有这个字符，前缀没吃掉
                use = c
                break

        if use == -1:
            continue  # 没有更大的字符，断点不成立

        # 构造答案
        ans = list(target[:i])
        ans.append(chr(use + 97))

        rem = [cnt[c] - pre[c] for c in range(26)]
        rem[use] -= 1

        for c in range(26):
            if rem[c] > 0:
                ans.extend(chr(c + 97) * rem[c])

        return ''.join(ans)

    return ""  # 从右扫到左都没找到断点——s 的最大排列也就等于 target
```

------

#### 尾声

所以这题的本质是什么？

不是“怎么超过 target”，而是“怎么用最懒的方式超过 target”。

回溯是在"不确定性"中搜索：每个位置都试一遍，随时读档，通关了也累得半死。

倒序贪心把"不确定性"消除了：从右往左倒着找，找到最后一个能改命的分歧点改一下，一遍扫描，O(n) 速通。

方向对了，剩下的都是躺赢。
