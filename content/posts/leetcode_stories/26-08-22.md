## 数字和与数字积：一场关于整除的混合双打

你收到一个正整数 `n`，和一个听起来像小学奥数热身赛的要求：

> 把它各位数字**加起来**，再把它各位数字**乘起来**，两个结果求和，问 `n` 能不能被这个和整除。

你盯着屏幕看了三秒，确认这不是力扣的每日整人环节。

------

**一、拆：把数字大卸八块**

最朴素的拆位操作：反复对 10 取余，把最后一位卸下来。和累加，积累乘，一趟搞定。

```python
def checkDivisibility(n: int) -> bool:
    a, b = 0, 1          # 和从 0 起加，积从 1 起乘——各自的"空包弹"
    tmp = n
    while tmp:
        tmp, r = divmod(tmp, 10)  # 拆下最后一位：商继续拆，余数留下
        a += r             		  # 加法帮：来者不拒
        b *= r             	      # 乘法帮：来者必翻
    return n % (a + b) == 0
```

`divmod` 一对二，商和余数同时拿到，省得你写一次整除、一次取模。循环里四行，干净利落。

------

**二、一行流：能跑，但别让面试官看见**

如果你只是想压行，还可以这么写：

```python
return n % (sum(map(int, str(n))) + eval('*'.join(str(n)))) == 0
```

原理：字符串转来转去，最后 `eval` 把 `1*2*3` 当代码跑——积就出来了。本地跑得飞起，提交也能 AC。

但 `eval` 这东西，属于"自己写着爽，别人看着慌"。如果输入要是不可控，一行 `eval` 就能帮用户把 `rm -rf /` 安排得明明白白。

所以这行代码的正确使用场景是：刷题、炫技、以及——被面试官要求解释为什么不该用它。

------

#### 彩蛋：整数指纹识别

你可能觉得这题就是个拆数字练习，刷完就完了。但对整数各位做混合运算，拿数字特征指纹干活这套路，在工程里出现得比你想的频繁：

- **信用卡 Luhn 校验**：每次刷卡，后台都会把卡号各位数字按规则加权求和，验一遍合法性。输错一位？当场拦截。但只防手滑，不防内鬼——想靠校验码挡住伪造，就像靠门禁照片防冒充，长得像就进去了。
- **混合哈希**：数据库索引、散列表、数据校验，经常对键值做“加、乘、异或”等混合运算生成散列值。你今天写的 `sum + product`，就是最朴素的混合哈希——丑是丑了点，但胜在简单。
- **弃九验算**：数字和 mod 9 同余于原数 mod 9，能快速检验加减乘除算错没算错。小学奥数老师的最强武器，计算器时代的活化石。

所以，你完全可以把今天学的发朋友圈：“研究了整数指纹提取在数据校验与哈希索引中的应用。”
