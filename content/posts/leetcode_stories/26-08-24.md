## 聚会杀手锏3.0！石子合并游戏教你秒算结局

> 朋友，上次用《求和游戏》三秒看穿胜负后，你在聚会上是不是已经成了"人形计算器"？别急，今天再升一级——《石子合并游戏》（LeetCode 1872）。这局看起来复杂得多：石子可以合并、可以分多轮、选择多到眼花。但真相是：**不管双方怎么操作，所有可能的分数早就被一张表焊死了。** 学会这招，你依然是聚会上最恐怖的"结局预言家"。

------

#### 游戏规则

道具：准备 `n` 个石子（或任何能写上数字的小东西）排成一排，数量随意，每枚标上一个数字。例如 `[-1, 2, -3, 4, -5]`。

你和朋友（Bob）轮流操作，你先手。每次轮到某人时，如果场上石子数 > 1：

1. 从**最左边**拿走**至少 2 个**石子（可以一次性拿走全部）；
2. 把这些石子的数字之和加到当前玩家的分数里；
3. 把这些石子**换成一个**新石子，面值就是它们的和，放回最左边。

比如你拿走前 3 个 `[-1, 2, -3]`，和为 -2，你记 -2 分，然后拿一个石子写上 `-2` 再放回去。队列变成 `[-2, 4, -5]`。接着轮到 Bob，他也按同样的规则操作：拿、合并、放回、记分。直到场上只剩 1个石子，游戏结束。

胜负结算：算 **你的总分 - 朋友 Bob 的总分**。差值为正，你赢；为负，Bob 赢；为零，平局。

你的目标当然是**最大化这个差值**，而你的朋友 Bob 则相反，想最小化这个差值。

听起来可能性很多对吧？其实——

------

#### 分数早就被焊死了！

你需要先算一张**前缀和表**——就是把数组从左往右累加：

比如 `[-1, 2, -3, 4, -5]` 的前缀和`pre_sum = [-1, 1, -2, 2, -3]`

**这张表为什么是游戏的关键？**看一次合并你就懂了。

假设你先手拿走前 3 个石子，得分`-1 + 2 + (-3) = -2 = pre_sum[2]`，放回的新石子价值也是 `-2`，此时场上变成 `[-2, 4, -5]`。如果朋友（Bob）下一步拿走剩下全部石子，他得分`(-2) + 4 + (-5) = -3`， `-3` 正好是 `pre_sum[4]`，也就是总和。

聪明的你一定发现了：**不管谁合并，每次得分一定是某个前缀和 pre_sum[j]。**

原因很简单：新石子的值就是被合并石子之和，也就是当前位置的前缀和；右边的石子没动过，之后继续合并，得分依然是前缀和。

于是这个游戏可以完全等价成：

> 前缀和数组 `pre_sum` 的下标从 0 到 n-1。
> 双方**轮流选一个下标 `j`，把 `pre_sum[j]` 加到自己分数里**。
> 每次选择的下标必须比上一次更大（严格递增）。
> **先手 的第一步必须从下标 1** 或更右开始选，因为至少要合并两个石子。

说白了，你们看起来在激烈博弈，其实不过是在这张前缀和表上**从左往右轮流挑数字**。

选择再多，天花板早就定好了。你能做的，只是在天花板下面选个最优姿势。

------

#### 必胜操作手册（趁你朋友还在研究规则的时候，迅速完成）

**第一步：算出前缀和**

把数组从左往右累加，得到前缀和数组 `pre_sum`。

比如`[-1, 2, -3, 4, -5]` -> 前缀和`pre_sum = [-1, 1, -2, 2, -3]`。

**第二步：倒推求分差**

定义 `f[i]`：当前玩家面对可选前缀和下标范围是 `i, i+1, ..., n-1` 时，能拿到的最优分数差（当前玩家得分 - 对手得分）。

先初始化：`f[n-1] = pre_sum[n-1]`。

然后从`i = n-2`开始，**从右往左倒着走**到 `i = 1`，对每个位置计算：

`f[i] = max(pre_sum[i] - f[i+1], f[i+1])`

最后 `f[1]` 就是你（Alice）先手时能拿到的最优分差（因为先手的第一步最小可选下标是 1）。

```python
def stoneGameVIII(stones: List[int]) -> int:
    n = len(stones)
    pre_sum = list(accumulate(stones))
    f = [0] * n
    f[-1] = pre_sum[-1]
    for i in range(n-2, 0, -1):
        f[i] = max(pre_sum[i]-f[i+1], f[i+1])
    return f[1]
```

**第三步：根据分差，决定你是装逼还是装死**

- 如果 `f[1] > 0`：这局你先手能赢 `f[1]` 分，可以放心大胆地开始。
- 如果 `f[1] <= 0`：别慌，演技上线。你可以突然看手机说“哎呀，我妈让我回家吃饭”，或者“这局你先手体验下，我看看你能不能翻盘”。

------

#### 等等，这公式哪儿来的？

你可能会想：凭啥从右往左一推就能算出来？这公式靠不靠谱？别急，这就来捋逻辑。

`f[i]` 的含义再默念一遍：当前玩家面对可选前缀和下标范围 `[i, n-1]` 时，能拿到的最优分数差（当前玩家得分 - 对手得分）。

站在位置 `i`，你可以选任意一个 `j >= i`，拿走 `pre_sum[j]` 分。然后轮到对方从 `j+1` 开始选，他会在剩余范围 `[j+1, n-1]` 里用最优策略，拿到他（对方）作为当前玩家的最优分差，也就是 `f[j+1]`。

所以你选 `j` 的净分差就是：`pre_sum[j] - f[j+1]`

你当然要最大化这个值，于是：**`f[i] = max( pre_sum[j] - f[j+1] )，对所有 j >= i`。**

**把 `j = i` 和 `j > i` 拆开**：`f[i] = max( pre_sum[i] - f[i+1] , max_{j>i}( pre_sum[j] - f[j+1] ) )`

后面那部分是什么？正好就是 `f[i+1]` 的定义——从 `i+1` 开始选的最优分差。

所以**递推公式最终简化为：`f[i] = max( pre_sum[i] - f[i+1] , f[i+1] )`**

边界 `f[n-1] = pre_sum[n-1]` 的意思是：当轮到某人时，他可以选择直接合并所有剩余石子（对应前缀和下标 `n-1`），一步结束游戏，对手没机会操作，所以分差就是总和。

于是从右往左一路推到 `i = 1`，就是你作为先手（Alice）的最优分差——因为先手的第一步最小可选下标是 1。

当你的朋友还觉得"合并石子"是个策略游戏时，你已经优雅地算完前缀和，提前看清了结局。

#### 实战演示：

假设朋友自信地摆出：`[-1, 2, -3, 4, -5]`：

你假装低头思考，实际心里在飞速倒推：

先算**前缀和**：`pre_sum = [-1, 1, -2, 2, -3]`

再**初始化**：`f[4] = pre_sum[4] = -3`。

然后**从右往左倒推**：

| i    | pre_sum[i] | f[i+1] | pre_sum[i] - f[i+1] | f[i]           |
| ---- | ---------- | ------ | ------------------- | -------------- |
| 3    | 2          | -3     | 5                   | max(5, -3) = 5 |
| 2    | -2         | 5      | -7                  | max(-7, 5) = 5 |
| 1    | 1          | 5      | -4                  | max(-4, 5) = 5 |

最终 `f[1] = 5`，也就是说，你（Alice）在最优策略下能赢 Bob **5 分**。

这时，你可以抬起头，淡定地说：“这局我先手，能赢你 **5 分**。请我喝奶茶吧。”

朋友不信，非要实际操作。你按策略走：

- 第一步合并前 4 个石子：`-1+2-3+4 = 2`，得分 2，剩余 `[2, -5]`。注意，这一步对应你选择了前缀和下标 3（`pre_sum[3]=2`），正是倒推中 `f[3]` 的最优选择。
- 朋友只能合并所有剩余：`2 + (-5) = -3`，得分 -3。
- 最终分差：你的分数 2 - 朋友的分数 (-3) = **5**。

朋友傻眼，奶茶到手。

```python
# 如果你嫌前缀和数组占地方，也可以用滚动变量简化：
def stoneGameVIII(stones: List[int]) -> int:
    n = len(stones)
    f = s = sum(stones)
    for i in range(n-2, 0, -1):
        s -= stones[i+1]
        f = max(s - f, f)
    return f
```
