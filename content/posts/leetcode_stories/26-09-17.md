## 正数局滑窗 carry 全场，负数局哈希默默兜底

读题，先看数据范围——`1 <= arr[i] <= 1000`。

**全是正数**。

这四个字意味着什么？意味着今天滑动窗口可以横着走。

------

#### 滑窗，启动

滑动窗口的约束：窗口和必须单调——右扩涨，左缩降。

既然今天全是正数，这条约束天然满足，双指针可以放心大胆地向右滑——每个元素最多被加一次、减一次，O(n) 的丝滑。

滑到什么程度要记一笔？窗口 `[l, r]` 的和恰好等于 `target` 的时候。

注意题目要的是**两个**不重叠的子数组。找到一个后，还得给它找配对。

指针从左往右滑，当前窗口 `[l, r]` 就是此刻最靠右的候选——能配对的只有它左边的 `arr[0..l-1]`。

左边那个选谁？暴力回头扫一遍？那就不是 O(n) 了。

既然左边是一路走过来的，不如边滑边记——提前准备好小抄。

**开一个前缀最优数组 `best`**：`best[l]` 记录 `arr[0..l-1]` 范围内和为 `target` 的最短子数组长度。窗口每前进一步，顺手更新这张小抄，查询只要 O(1)。

当前窗口 `[l, r]` 长度是 `r - l + 1`，左边最短直接查表：`best[l]`——它管的是 `arr[0..l-1]`，和当前窗口天然不重叠。两者相加，全局取最小：`ans = min(ans, best[l] + (r - l + 1))`。

```python
def minSumOfLengths(arr: List[int], target: int) -> int:
    n = len(arr)
    best = [inf] * (n + 1)  
    ans = inf
    cur = l = 0

    for r in range(n):
        cur += arr[r]

        while cur > target:
            cur -= arr[l]
            l += 1

        if cur == target:
            length = r - l + 1
            if best[l] != inf:
                ans = min(ans, best[l] + length)
            best[r + 1] = min(best[r], length)
        else:
            best[r + 1] = best[r]

    return -1 if ans == inf else ans
```

滑窗负责当下，小抄负责历史，一趟扫描，干净利落。

------

#### 但是——

这一切丝滑的前提是：`1 <= arr[i]`。

如果这行约束消失，会发生什么？

假设数组里混进了负数：`[3, -1, 2, 4, -3, 5]`，`target = 4`。

窗口扩到 `[3, -1, 2]`，和是 4——找到了！继续扩，加个 4，和变 8，超了。左指针收？等等，继续扩，后面那个 `-3` 会把和拉回来，可能又等于 4。

**窗口和不再单调。** 右扩不一定增大，左缩不一定减小——负数让和反复横跳。

滑窗，失效。

------

#### 前缀和 + 哈希

既然单调性没了，那就别依赖单调性——不滑窗，**记前缀和**。

从数组开头一路加过来，每到一个位置 `i`，就把 `arr[0..i]` 的总和记下来，这就是前缀和 `prefix`。

如果之前某个位置 `j` 的前缀和恰好是 `prefix - target`，那 `arr[j+1..i]` 这一段，和就是 `target`。

说白了，两个前缀和相减，中间那段就是你要的子数组。没有窗口，不用收缩，纯减法。

至于怎么快速找"之前有没有 `prefix - target`"——**哈希表。**

用 `pos` 记录每个前缀和**最后一次**出现的索引（同一个前缀和可能出现多次，越晚出现，`i - j` 越短，子数组越短）。实际上，`pos` 就是通用版的"窗口"——不靠指针收缩找目标，靠哈希查表一步到位。

找到子数组了，同样还得配对。和滑窗版一样的问题：当前这段左边配谁？答案也一样——查左边历史最优。

还是用那本小抄：`best[l]` 记录 `arr[0..l-1]` 中和为 `target` 的最短子数组长度。找到一段就查 `best[l]` 配对，顺手更新 `best[i+1]`。

```python
def minSumOfLengths(arr: List[int], target: int) -> int:
    n = len(arr)
    best = [inf] * (n + 1)  
    ans = inf
    prefix = 0
    pos = {0: -1}  # 空前缀和为 0，索引记为 -1

    for i in range(n):
        prefix += arr[i]

        if prefix - target in pos:
            l = pos[prefix - target] + 1
            length = i - l + 1
            if best[l] != inf:
                ans = min(ans, best[l] + length)
            best[i + 1] = min(best[i], length)
        else:
            best[i + 1] = best[i]

        pos[prefix] = i

    return -1 if ans == inf else ans
```

小抄没变，配对逻辑没变，只是找子数组的方式从“窗口收缩”换成了“哈希查表”。

------

#### 复盘

两种解法，配对逻辑一模一样——都是查左边历史最优。

区别只在"怎么找和为 target 的子数组"：一个靠双指针收缩窗口，一个靠哈希表查前缀和。

滑窗更简洁、常数更小，但有一条隐性门槛：数组不能含负数。

前缀和 + 哈希多一个哈希表的开销，但胜在通用——来什么数都不怕。

今天 `arr[i] ≥ 1`，滑窗直接起飞。哪天 `arr[i]` 变成任意整数——也别慌，前缀和 + 哈希给你兜底。

看清手里什么牌，再决定出什么招。
