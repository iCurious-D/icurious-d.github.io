## 从左往右点名，第一个答到就散会

有些题是 DP，有些题是图论，有些题是连续打卡克星。

而今天这题，是早退模拟器——从左往右点名，第一个答到就散会。

------

#### 数位和的两种姿势

**姿势一：字符串流**

```python
sum(map(int, str(num)))
```

一键三连：

1. `str(num)`：把数字拍成字符串；
2. `map(int, ...)`：逐字符转回整数；
3. `sum(...)`：一把梭求和。

这套连招几乎全在 CPython 的 C 层跑。你在这边摸鱼，它在底层飙车。

**姿势二：取模流**

```python
s = 0
while num:
    s += num % 10
    num //= 10
```

经典数学做法：每次取末位、累加、截断。

逻辑清晰，适合面试时展示你懂十进制。但每一位都要跑一轮 Python 字节码：取模、整除、赋值、判断，四条指令再乘上位数。

**谁快？**

数据量小，复杂度都是 O(n·d)，但姿势一的常数因子小得多。内置函数的循环在 C 层跑，而手写的 while 每一步都要经过解释器调度。

Python 的经典定律：**能用内置函数就别自己用 Python 搬砖**。

------

#### 数据范围的暗线

注意数据范围：`nums[i] <= 1000`。

但数位和最大的并不是 `1000`。`1000` 的数位和只有 `1 + 0 + 0 + 0 = 1`。真正的大哥是 `999`：

> 999 → 9 + 9 + 9 = **27**

也就是说，数位和的值域其实只有 `[0, 27]`。从下标 `28` 开始永远不可能匹配——真正的早退模拟器。

当然，题目数据量才 `100`，你硬扫完也没人会判你 TLE。

```python
def smallestIndex(nums: List[int]) -> int:
    for i in range(min(len(nums), 28)):
        if sum(map(int, str(nums[i]))) == i:
            return i
    return -1
```

时间复杂度 `O(min(n, 28)·d)`，空间复杂度 `O(d)`。`d` 是位数，最大 4，基本等于常数。

------

#### 尾声：一个没用的冷知识

反复对一个数求数位和，最终会收敛到 1~9 之间的一个数，叫**数字根**。

比如 355 → 3+5+5 = 13 → 1+3 = 4。

公式：`1 + (n - 1) % 9`，一秒出结果。

这套模 9 同余的思路，古称“弃九验算法”，用来检查乘法有没有算错。

跟本题没关系。

但知道总比不知道好——下次相亲可以拿来暖场。
