## 心态崩了？return -1

想象一下：你正站在数组的第 `i` 个位置上，左顾右盼。

往回看，有你一路走来的**巅峰** `max(nums[0..i])`；往前看，有你即将踏入的**低谷** `min(nums[i..n-1])`。两者的落差，就是你的**不稳定值**——落差越大，心态越容易崩。

崩不崩的临界线叫 `k`。落差不超 `k`，你还能强装镇定；一旦超过，你当场崩给所有人看。

这里有个容易一眼扫过去的细节：`i` 同时属于两边。这不是笔误——`i`是你的现在，不能置身事外。

问你：从 0 往右走，**第一个心态没崩的位置在哪**？找到就赶紧返回，别磨蹭。要是每个位置都能让你崩成渣，返回 `-1`——这数组没救了，换个题目重新做人。

------

#### 一、暴力切片：题面的 Python 直译

题目给了 `n ≤ 100`，意思很明确：你随便写，别把服务器搞挂就行。

```python
def firstStableIndex(self, nums: list[int], k: int) -> int: 
    n = len(nums) 
    for i in range(n): 
        if max(nums[:i+1]) - min(nums[i:]) <= k: 
            return i
	return -1
```

五行，收工。它的优点在于：跟题面完全对应，几乎不可能写错。但代价也很明显：

1. `nums[:i+1]` 和 `nums[i:]` 是**切片拷贝**——每路过一个下标，就新建两个临时列表，把元素挨个搬一遍。GC 在后台忙得跟外卖小哥似的。
2. `max` 和 `min` 各扫一趟，每个 `i` 都得从头数一遍。

`n` 个下标 × 每个 `O(n)` = **O(n²)**，外加 `n` 轮纯搬运的内存开销。好在`n = 100` ，一万次比较，力扣会放过你。但面试官要是看见你写这玩意儿，脸上可能会浮现一种"不稳定"的微笑。

------

#### 二、从“每次重算”到“一次算好，边扫边用”

暴力的问题很明显：前缀最大值被从头重算了 `n` 次；后缀最小值也被从头重算了 `n` 次。

而这两个量偏偏都是**增量可维护**的：

- 往右走一步，前缀最大值要么不变，要么被新元素顶上去；
- 往右走一步，后缀少一个元素，最小值要么不变，要么变大。

走一步就能更新的东西，凭什么每次从头数？

**优化思路一句话：后缀最小值先算好存起来，前缀最大值边走边算。**

为什么两者待遇不一样？因为要找的是**最小下标**，判定必须正向扫：

- 前缀最大值在正向扫时顺手产生，**访问顺序 == 生成顺序**，一个滚动变量就够，犯不着开数组；
- 后缀最小值必须**从右往左**才推得出来，跟正向扫的方向对不上，只能先建好数组备着。

```python
def firstStableIndex(self, nums: list[int], k: int) -> int: n = len(nums)
    n = len(nums)
    # 后缀最小值：suf_min[i] = min(nums[i..n-1])，从右往左递推
    suf_min = [0] * n
    suf_min[n - 1] = nums[-1]
    for i in range(n - 2, -1, -1):
        suf_min[i] = min(suf_min[i + 1], nums[i])

    # 前缀最大值：滚动变量，O(1) 空间
    pre_max = nums[0]
    for i, x in enumerate(nums):
        if x > pre_max:                   
            pre_max = x
        if pre_max - suf_min[i] <= k:
            return i   # 正向扫，第一个命中就是最小下标
    return -1
```

时间 O(n)，空间 O(n)——就一个后缀数组，前缀那边连数组都没开。

#### 三：accumulate：炫技可以，稳住别浪

Python 的 `itertools.accumulate` 可以写得非常优雅：

```python
def firstStableIndex(self, nums: list[int], k: int) -> int: 
    # 反向累积累 min 再翻回来，就是后缀最小值数组
    suf_min = list(accumulate(reversed(nums), min))[::-1]
    # 正向累积累 max 就是前缀最大值序列，zip 到一起逐个判定
    for i, (pm, sm) in enumerate(zip(accumulate(nums, max), suf_min)):
        if pm - sm <= k:
            return i
    return -1
```

`accumulate`  在 C 层跑，Python 解释器只管最后那趟 `zip`，省了一整趟字节码循环；还自带哨兵——第一个输出就是第一个元素，反向边界自动填好，妈妈再也不用担心你把 `n-2` 写成 `n-1`。

但天下没有免费的午餐，代价有两条。

**一是内存。** `[::-1]` 是一次实打实的 O(n) 拷贝，那一瞬间峰值 **2n**——旧列表还没被回收，新的已经生出来了。

**二是改不动。** `zip` 是个封闭结构，**现在有多短，未来就有多难改**：想加第三个序列？想在条件里掺进 `i` 本身？想顺手统计一下最小不稳定值？每一条都得把它拆开，退回显式循环。

至于面试——写顺了，面试官眼前一亮；写卡了，你俩一起进入"不稳定状态"。

建议：现场用显式版，全 accumulate 版留着发朋友圈。

成年人当然可以两个都写，甚至混着写（第一趟 accumulate 抢速度，第二趟显式循环留余地），看气氛。

#### 彩蛋：这套骨架还能干什么？

同一套“前缀最值 + 后缀最值”骨架，换个皮就是另一批题：

- **接雨水**：每格能接的水 = `min(左边最高, 右边最高) - 自己的高度`
- **柱状图最大矩形**：本质上也是前后缀最值问题
- **买卖股票的最佳时机**：两个方向的最值在对撞

说到股票，这题在金融圈有个失散多年的兄弟：**回撤（drawdown）**。`max(nums[0..i])` 是持仓以来的最高净值，`min(nums[i..n-1])` 是之后会跌到的最低谷，两者之差就是最坏情况下会亏多少。

风控部门每天盯的就是这个数。只不过，力扣版的回撤给你**开了天眼**——提前知道谷底在哪，永远不会“抄底抄在半山腰”。
